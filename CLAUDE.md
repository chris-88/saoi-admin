# CLAUDE.md: saoi-admin (the presenter console)

## What this is

The operator's console for Saoi, served at `https://admin.saoi.ie`: case inspector, event
simulator, notifications, persona, guardrails, goals and needs, products and rates, forms,
analytics, feedback and collaborators (§37 to §44 of the spec). A static SPA on GitHub Pages
behind a real email sign-in. It holds no business logic: every action is a `saoi-api` admin
route, and admin status is checked by the server on every call, never by this app.

Until 2026-11-09 it was `#/admin/*` inside the customer app. Its routes sit at the root here
(`#/case/:id`, `#/persona`, ...); `#/admin/*` redirects to the same screen without the prefix,
and `app.saoi.ie/#/admin/*` redirects here.

Naming: everything is `saoi`; `Saoirse` is only the assistant as a persona.

## Operating philosophy: lean surface, high floor

Two rules that look opposed but aren't:

1. **Keep the surface lean.** Don't add speculative features, abstractions, or dependencies. Every new library is a decision that must be justified by a concrete, present need — not "we might want it." Prefer the platform and what's already in the stack before reaching for something new.
2. **Keep the floor high.** Strict types, tests, linting, CI gates, accessibility, and real error handling are **not** "later" work — they are baseline and apply from the first commit. Restraint governs _scope_; it never governs _craft_.

When these tension, craft wins. A small, correct, well-tested feature beats a large, untested one.

## Layout

- `src/admin/`: the screens. `adminClient.ts` parses every payload with its Zod contract.
- `src/lib/saoiApi.ts`: one typed route per admin action, through `src/api/client.ts`, which adds
  the Supabase access token as a bearer.
- `src/api/schema.d.ts`: generated by `npm run api:generate`; never edited by hand.
- Market data (`src/admin/MarketScreen.tsx`): one card per product from
  `GET /api/admin/market/views` (the engine's views: a bank row and its CCPC twin folded, CCPC's
  terms in a ladder); a card's source badges open the raw row and its history from
  `GET /api/admin/market-products`. One tree, three layouts by viewport: a phone (under 768px)
  has the filters in a bottom sheet over one column, a tablet (768 to 1023, the iPad PWA in
  portrait) a foldable panel above two, the desk a sticky left rail beside three.
- The shell's sidebar (`AdminConsole.tsx`, `useSidebarOpen`): open at 1024px and up; under it
  (768 to 1023, the iPad in portrait) it starts as the icon rail and remembers the viewer's
  choice in `localStorage`; under 768 it is a drawer.
- `src/shared/`: copies of the backend's contracts, domain, persona, refusals and tenant domain
  config that the screens import (`@contracts`, `@domain`, `@llm`, `@tenants`).
  `npm run shared:sync` refreshes them from `../saoi` (or `SAOI_DIR`), `npm run shared:check`
  reports drift. Never edit a copy here.
- `src/saoirse/`: the avatar and mark only, for the sidebar.

## Engineering standards

- No `any`. No non-null `!` outside tests. Exhaustive `switch` with `assertNever`.
- Query keys from `src/lib/queryKeys.ts`; mutations invalidate by key.
- Destructive actions send `confirm: true`, which the service requires.
- `scripts/check-bundle-secrets.ts` fails the build if a credential shape reaches `dist/`. There is
  no size budget: the console is opened by one operator on a laptop.

## PWA

The console installs to a home screen as "Saoi admin" (2026-11-13), on saoi-web's rules: a deploy
must reach an installed app without reinstalling it (vault decision 2026-11-12).

- The worker precaches the shell and never caches API responses: `api.saoi.ie` (saoi-api and
  the self-hosted Supabase) matches no route, so it goes to the network uncached, and Realtime is
  a WebSocket the worker never sees. Navigations are network-first (`NetworkOnly`, the precached
  `index.html` only when the network fails), so a deploy reaches an open install on its next open;
  the precache is the offline fallback only. No `navigateFallback`, `directoryIndex: null`;
  `scripts/check-service-worker.ts` (in `check:bundle`, so in `npm run check` and the deploy)
  fails the build if `dist/sw.js` drifts or the manifest's icons are missing.
- An open page looks for a new worker whenever it comes back into view and hourly
  (`checkForUpdates`). The new worker's takeover reloads the page (`reloadWhenWorkerTakesOver`),
  but never over unsaved edits or a save in flight, hidden or not (`src/app/reloadGate.ts`: edit
  screens call `useReloadHold(dirty || saving)`; persona, products and rates, and the goal and
  need wording sheet do). A new edit screen with unsaved state calls it too.
- Sign-in is `signInWithPassword` with the session in `localStorage`, so there is no redirect to
  land and an installed app keeps its session. iOS gives a home-screen app its own storage, so
  the first open of the installed app asks for a sign-in once.
- Icons: `scripts/icons/admin-icon.svg` (192, 512) and `admin-icon-maskable.svg` (maskable 512,
  Apple touch icon), rendered to the committed PNGs in `public/icons/` by
  `scripts/render-icons.sh` (rsvg-convert). Saoirse's face on the deep teal with a slider badge,
  so it is told apart from the customer app's icon.
- Cloudflare: `admin.saoi.ie/*sw.js` must bypass the edge cache (a page rule outside this repo,
  as `app.saoi.ie` has), so a new `sw.js` is seen as soon as Pages serves it.

## Environment

`.env` (names in `.env.example`): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`,
`VITE_SAOI_API_URL` (required), `VITE_SENTRY_DSN`, `VITE_BASE_PATH`. Repo variables in CI.

The origin must be in `CORS_ORIGINS` of `saoi-api` and in the auth stack's redirect allow list
(`~/code/infra`, `stacks/saoi-api/docker-compose.yml` and `stacks/saoi/.env.local-overrides`).

## CI and deploy

- `ci.yml`: `npm run check` and a production dependency audit.
- `deploy-pages.yml` after CI passes on `main`. Rolling deploy: merging to `main` ships.
- When `saoi-api` changes an admin route, run `npm run api:generate` and `npm run shared:sync`.
